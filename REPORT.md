# Отчет по лабораторной работе: GitHub Actions

## Ответы на контрольные вопросы

1. **Из каких элементов состоит workflow и как они вложены друг в друга?**
   Workflow делится на 3 уровня:
   - **Workflow** — сам файл автоматизации, где задано событие (`on`) и список работ (`jobs`).
   - **Job** — отдельная задача, которая запускается на виртуальной машине (`runs-on`).
   - **Step** — конкретные шаги внутри задачи (команды `run` или готовые экшены `uses`).

2. **Чем job отличается от step?**
   - **Job** выполняется на изолированной виртуальной машине. Разные jobs по умолчанию работают параллельно и не видят файлы друг друга.
   - **Step** — это шаг внутри одной job. Все шаги идут строго по очереди на одной машине и имеют доступ к общим файлам.

3. **Чем запуск по push отличается от запуска кнопкой (workflow_dispatch)?**
   - `push` — запускается автоматически каждый раз, когда отправляешь коммит в репозиторий.
   - `workflow_dispatch` — запускается вручную кнопкой в интерфейсе GitHub.

4. **Как безопасно передать в workflow пароль или токен?**
   Сохранить его в настройках репозитория (*Settings -> Secrets and variables -> Actions*), а в YAML-файле вызывать через `${{ secrets.ИМЯ_СЕКРЕТА }}`. GitHub сам скроет его значение в логах звездочками (`***`).

5. **Что такое артефакт и зачем он нужен?**
   Это файл или папка, сохраненная во время работы пайплайна. Нужен для того, чтобы скачивать результаты сборки/тестов или передавать файлы между разными jobs.

6. **Как заставить один job дождаться завершения другого? Зачем нужен линтер, если есть тесты?**
   - Чтобы job ждала другую, нужно добавить строку `needs: <имя_job>`.
   - **Линтер** проверяет опечатки и синтаксис без запуска кода, а **тесты** проверяют правильность работы программы. Линтер помогает быстро поймать глупые ошибки ещё до запуска долгих тестов.
